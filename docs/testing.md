# Проверка чата

Проект: React + TypeScript, текстовый Telegram-чат через GREEN-API. Дата финального прогона: 03.10.2026.

## Что нашли и поправили

Это воспроизведённые ошибки исходной версии, не список косметических замечаний.

| Ошибка | Как проявлялась | Исправление и проверка |
|---|---|---|
| Старое событие об авторизации | Инстанс уже подключён, но в очереди лежит старое `notAuthorized` или `starting`. Приём останавливался перед новым сообщением. | После подтверждения события запрашиваем текущее состояние. Тесты проверяют старое событие и настоящую потерю авторизации. `pollNotifications.ts`, `pollNotifications.test.ts`. |
| Постоянные ошибки API | `400/404` запускали бесконечные повторы получения. Повтор не исправляет адрес или настройки. | Приём приостанавливается с действием для пользователя. `408/429`, сеть и `5xx` сохраняют повтор с задержкой. Проверены получение и подтверждение. |
| Группа выглядит как человек | В заголовок группового чата попадало имя автора сообщения. Ответ уходил группе, хотя интерфейс выглядел как личный диалог. | Используем название группы, показываем «Групповой чат» / «Группа». Проверены нормализация, reducer и интерфейс. |
| Стирается новый черновик | Отправил A, пока запрос шёл исправил на B, затем снова на A. Ответ API очищал этот новый текст. | Сравниваем ревизию черновика, а не только его строку. Regression в `App.test.tsx`. |
| Последнее сообщение уезжает за экран | Уменьшение высоты окна или рост поля ввода скрывали нижние сообщения. | `ResizeObserver` удерживает низ, если пользователь уже был внизу. Если он читает старые сообщения, позицию сохраняем. Браузерный тест на оба режима. |
| Переполнение Retry-After | Корректная длинная задержка превышала предел `setTimeout` и превращалась в почти мгновенный повтор. Чрезмерное число секунд могло стать `Infinity`. | Ждём конечную задержку частями, выход отменяет ожидание. Неконечное значение заголовка не принимаем. Проверки fake timers и API-парсера. |
| Теряется окончательная ошибка отправки | Ответ SendMessage потерялся, затем пришёл `failed/noAccount` с неизвестным локально ID. Событие подтверждалось без видимого сообщения об ошибке. | Показываем ошибку чата и сохраняем статус для возможного позднего ответа. Не создаём выдуманное сообщение. Проверены оба статуса. |
| Скрытая ошибка API-адреса | Некорректный адрес в закрытых дополнительных настройках блокировал отправку формы без видимого объяснения. | Проверка показывает поле и ошибку. Браузерная regression на desktop и mobile. |

## Как повторить проверки

```sh
npm ci
npm run typecheck
npx tsc --project tests/tsconfig.json --pretty false
npm run lint
npm test
npx playwright install chromium
npm run test:e2e
npm run build
```

В CI Chromium ставится с системными зависимостями. В браузерных тестах проверяем экран подключения, создание чата, текст, повторы, статусы, мобильные переходы, две вкладки и регрессии выше. API перехватывается тестовым стендом. Рабочего ключа, настоящих номеров и переписки в этих тестах нет.

## Что эти тесты не доказывают

Моки в тестах позволяют воспроизвести таймаут, повреждённое событие и ответ в неудобный момент. Они не проверяют доступность самого GREEN-API и Telegram. Настоящий обмен проверяется отдельно с согласованным получателем. Автодеплой не отправляет сообщения чужим людям.

После публикации отдельно проверяются HTTPS, release marker, форма, обе инструкции, мобильный вид и скачивание ZIP. Для отката сохраняется предыдущий статический релиз. Проверка истории на секреты выполняется до публикации; тестовые примеры в скриншотах вымышленные.
